# Code Search Architecture

## Goal

Build a personal-use automation system that produces faceless YouTube videos for the `Code Search` channel with strong branding, acceptable originality, and minimal daily manual work.

The first priority is a daily roundup lane that can run with near-autopilot. Secondary lanes are manual `versus` videos and deeper authority videos.

The broader channel opportunity includes both open-source and paid software. Paid software matters not only for content variety but also for affiliate revenue opportunities.

## Content Lanes

### 1. Daily Roundup

- Highest priority
- Target output: daily
- Format: `1-3s` splash, `10-15` tools, `25-50s` per tool, short neutral outro
- Goal: speed, consistency, daily volume
- Scope: trending repositories, open tools, and adjacent technical software from the daily discovery lane
- Non-goal: dedicated paid-software reviews or affiliate-first picks

### 2. Battle Videos

- Manual for now
- Format: `Tool A vs Tool B` or `Open Source vs Paid`
- Goal: stronger click-through and clearer editorial framing
- Primary lane for mixed comparisons across open-source and paid software
- Affiliate-friendly paid tools belong here, but this lane is not paid-only

### 3. Authority Deep Dives

- Manual for now
- Format: one topic or one tool with more context and judgment
- Goal: long-term channel authority
- Secondary lane for open-source or paid software reviews, workflow comparisons, and “is it worth paying for?” evaluations

## MVP Scope

The MVP is the smallest system that can produce a daily roundup bundle automatically:

- `video.mp4`
- `thumbnail.png`
- `title.txt`
- `description.txt`
- `manifest.json`
- `sources.txt`

Delivery target:

- local output folder first
- then Google Drive or a synced Drive folder

The dashboard is intentionally out of MVP scope. It should only be built after the command-line pipeline is stable.

## Core Architecture

The current Remotion project hardcodes episode data inside `src/Root.tsx`. That is fine for a hand-authored prototype but not for daily automation.

The target architecture splits the system into two layers:

### 1. Episode Generator

Responsible for:

- sourcing candidate tools
- ranking and filtering them
- writing short scripts
- generating title and description text
- generating or collecting screenshots/recordings
- generating TTS audio
- writing a daily `manifest.json`

This layer is the content pipeline.

### 2. Video Renderer

Responsible for:

- loading a generated manifest
- rendering scenes in Remotion
- composing intro, per-tool segments, and outro
- exporting final video

This layer is the rendering engine.

## Manifest-Driven Rendering

Instead of editing `src/Root.tsx` for every episode, the pipeline should generate an episode manifest and the renderer should consume that manifest.

Example responsibilities of the manifest:

- episode metadata
- date and episode number
- intro and outro lines
- list of selected tools
- script per tool
- screenshot or recording asset paths
- audio file paths
- duration metadata
- thumbnail text

This lets the generator create a new episode without touching renderer code.

## Pipeline Responsibilities

### Tool Sourcing

Handled by the generator layer.

Initial source targets:

- GitHub trending and GitHub search
- Hacker News where useful
- ClawHub or adjacent agent/skill sources where useful
- seed keyword searches for `Claude Code`, `Codex`, `MCP`, `agent`, `screen recorder`, `dev tools`, `automation`
- later, curated paid software sources and affiliate-friendly review targets

### Ranking and Selection

Handled by the generator layer.

Initial scoring factors:

- trend strength
- novelty
- audience fit
- visual potential
- clarity of use case
- monetization opportunity for non-daily lanes

### Script Generation

Handled by the generator layer.

Daily per-tool script shape:

1. problem hook
2. what it is
3. why developers care
4. optional light note if supported by evidence

The daily lane should avoid aggressive end-of-video verdicts.

### Audio

Handled by the generator layer.

Initial plan:

- one locked female ElevenLabs voice
- intro line
- one narration clip per tool
- short neutral outro

### Screen Capture

Handled before final render, as part of asset generation.

There are two supported capture modes:

#### Synthetic Motion Mode

- screenshot-based
- motion and cursor are generated by the renderer
- fastest and most stable for daily MVP

#### Real Capture Mode

- browser or app is driven automatically
- Recordly captures real cursor movement and click activity
- better authenticity, better for premium/manual formats

## Hybrid Capture Strategy

This project should use a hybrid approach.

### Daily Roundup

- default to screenshot-based segments with polished synthetic motion
- no lower-third required
- add QA snapshots after render to verify motion quality

### Battle / Deep Dive

- use real interaction capture where valuable
- drive the browser or app with automation
- capture with Recordly when the interaction itself matters

This keeps daily production fast while leaving room for more authentic showcase videos.

## Editorial Fit Model

Selection should not be based on whether a tool is open source or paid. The real question is whether the channel can make a credible software-builder case for why the audience should care.

Three fit buckets should be used:

### Core

- AI coding tools
- agent frameworks
- Claude Code, Codex, MCP, automation, screen-recording, developer workflow tools
- software builders would plausibly install soon

### Adjacent

- technical software with a credible developer or builder use case
- APIs, media tooling, data sources, dashboards, infrastructure, security, technical product software
- paid software that supports creator, automation, or developer workflows

### Exclude

- sponsor listings and obvious non-project entries
- repeated variants that add little editorial value in the same episode
- items the channel cannot frame credibly for developers, automation users, or software builders

## Smooth Cursor Animation Strategy

Three layers can contribute here:

### 1. Current Remotion Cursor

- already present in `src/components/SkillCard.tsx`
- generates fake but polished cursor motion and scrolling
- useful for MVP daily videos

### 2. Browser Driver

- should automate site visits, clicks, and navigation
- best fit: `agent-browser` skill / browser automation lane

### 3. Recordly Capture + Cursor Overlay

- records real cursor telemetry
- supports cursor smoothing
- supports click animation
- supports zoom region suggestions

This is the preferred lane when realism matters.

## Quality Guardrails

Every rendered episode should produce QA stills or previews to verify:

- cursor visible and moving
- scroll motion happened
- title card readable
- tool visuals not stuck
- framing not cropped badly
- intro splash duration correct

If QA checks fail, the episode should be flagged instead of silently shipping.

## Branding Rules

- channel brand is `Code Search`, not `OpenClaw`
- intro splash should be `1-3` seconds max
- no lower-third by default for the daily lane
- use existing raccoon and aurora brand direction as the visual anchor
- daily voice should be consistent and understated
- outro should be short and neutral

## Dashboard Direction

The dashboard is a later wrapper around the working pipeline.

Initial target tabs:

- Daily Engine
- Battle Studio
- Deep Dive Studio
- Assets
- Analytics placeholder

The dashboard should not block MVP content production.

## Open Decisions

- whether daily videos default to screenshots only or selectively use short Recordly captures
- exact ElevenLabs voice ID and generation settings

- final daily outro phrasing
