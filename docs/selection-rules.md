# Selection Rules

## Purpose

These rules govern how `Code Search` chooses tools and software for videos.

The system should not narrowly optimize for “AI coding tool” only. It should optimize for **credible audience fit** for people interested in:

- software
- developer tools
- agent workflows
- automation
- technical products
- creator-adjacent software with a real software-builder use case

The channel can cover both open-source and paid products.

## Editorial Principle

The main selection question is:

`Can we explain why a developer, software builder, automation user, or technical creator would care about this?`

If yes, the candidate may belong.

If no, it should be excluded even if it is trending.

## Fit Buckets

### Core

Candidates in this bucket are the best default fit for the channel.

Examples:

- AI coding tools
- agent harnesses
- Claude Code or Codex ecosystem tools
- MCP servers and tooling
- dev workflow software
- screen-recording tools for software demos
- automation tools used by builders
- technical SaaS products with direct software workflow relevance

### Adjacent

Candidates in this bucket may still belong if the framing is strong.

Examples:

- technical media software
- APIs and data sources
- infrastructure and security software
- home-lab and ops-adjacent tools
- vertical software with clear developer usage
- paid tools with strong workflow relevance

These are valid when the episode can make a real case for use.

### Exclude

Candidates in this bucket should not be selected.

Examples:

- sponsor pages
- obvious duplicate variants in the same episode
- projects with no credible software-builder framing
- trend noise that only got selected due to stars but offers weak content value

## Daily Roundup Rules

The daily roundup should lean heavily toward `core` picks and only include `adjacent` picks when:

- they are visually interesting
- the use case can be explained quickly
- they improve variety without diluting the channel identity
- they come from the daily discovery lane rather than a separate paid-review pipeline

The daily lane should avoid:

- too many duplicates in the same topical family
- highly abstract research repos with no clear user-facing angle
- products that require too much setup explanation
- dedicated paid-software review targets chosen mainly for affiliate value

## Battle Video Rules

Battle videos can include:

- open-source vs open-source
- open source vs paid
- Tool A vs Tool B
- best-for-beginners vs best-for-power-users
- affiliate-friendly paid tools where the comparison is honest and useful

This lane is not restricted to paid software. It is the main place for strong comparisons, whether the inputs are open, paid, or mixed.

These videos can be more opinionated and more monetization-aware than the daily lane.

## Authority Video Rules

Authority deep dives can include:

- open-source software
- paid software
- workflow stacks
- “is it worth paying for?” reviews
- affiliate opportunities where they genuinely help the viewer

The goal is trusted judgment, not trend aggregation.

## Duplicate Handling

Do not select multiple items from the same family in the same daily episode unless there is a strong editorial reason.

Examples of likely duplicate families:

- a main project and a language-region fork
- a base project and a lightly renamed repackaging
- multiple wrappers around the same exact idea

Duplicates should be penalized, not automatically banned, so a human or later rule layer can still override.

## README Enrichment Rule

Do not rely only on the trending one-line summary when judging a candidate.

Before a candidate is accepted into a final script set, the system should read:

- the README when available
- docs or homepage when the README is weak

This is especially important for:

- vague repo descriptions
- agent platforms
- paid software
- repos with unclear user value

## Monetization Rule

Paid software is part of the strategy, especially outside the daily lane.

Selection logic should preserve the ability to review:

- paid developer tools
- creator software
- automation products
- affiliate-friendly products

Monetization opportunity should never be the only reason to include a tool, but it is a legitimate positive factor when audience fit is real.

For clarity:

- daily roundup: not the place for separate paid-software targeting
- battle videos: yes
- authority deep dives: yes
